# Design: `serve` live version history (sub-project A1)

**Date:** 2026-07-04
**Status:** Approved (design), pending implementation plan
**Component:** `internal` (serve layer)

## Summary

In `mkdown serve`, add a right-side **version history sidebar** that records each
save during the editing session and lets you click back to view any earlier
rendered version. This is sub-project **A1** of a larger version/diff feature —
**live versions only**; git history (A2) and inline section diffs (B) build on
this substrate later.

```
mkdown serve readme.md
→ live preview on the left, version timeline on the right
[edit + save] → a new "edit HH:MM:SS" entry appears at the top; the preview follows
[click an older entry] → the preview shows that snapshot; "Back to Live" returns to following
```

## Decisions (settled in brainstorming, fixed for A1)

1. **Serve-only.** The sidebar exists only under `mkdown serve`. Standalone
   `mkdown file.md` output is **byte-for-byte unchanged** — the converter and
   the shared `default.html` template get zero version/sidebar markup.
2. **Always on in serve.** Every `serve` session shows the sidebar (no flag).
3. **Live versions only.** Versions come from the editing session, not git.
   Git history (A2) slots into the same store/UI additively later.
4. **Store rendered snapshots.** Each version keeps its rendered HTML (serve
   already renders on each change), so viewing a version just returns stored
   bytes — no `RenderBytes`/re-render needed in A1. (`RenderBytes` is deferred
   to A2, where git gives source, not rendered output.)
5. **Iframe shell.** The content document loads in an `<iframe>` (pristine,
   self-contained, no injection); the sidebar lives in the parent shell. This
   fits mkdown's self-contained output and is simpler than DOM-swapping.

## Architecture

All of this lives in the **serve layer** (`internal/serve.go` and new sibling
files). The converter is untouched.

### Version store (replaces/extends `serveHolder`)

An in-memory, mutex-guarded ordered list of versions. A `version`:

```
{ id int; kind string; label string; ts time.Time; html []byte }
```

- `id` is monotonic (1, 2, 3, …). The highest id is the **live head**.
- `html` is the **pristine** rendered snapshot — `Converter.Render` output, or a
  standalone error page on a render failure. It carries **no** injected reload
  script: the current per-content `reloadScript` injection in `serve.go` is
  removed, and reload is handled by the shell (it reloads the iframe). The iframe
  loads this html as-is, so a version's content equals the standalone output.
- **At startup:** render the working-tree content → version 1, kind `opened`.
- **On each detected change** (the existing `statSig` poll): render; if the
  rendered HTML equals the current head's `html`, **skip** (dedup — a `touch`
  with no content change adds nothing); otherwise append a new version, kind
  `edit`, with the current time.
- **No cap in A1** (a session rarely produces hundreds of distinct saves); noted
  as a maintenance follow-up.

Concurrency: the poll goroutine appends; HTTP handlers read. Guard with a
`sync.RWMutex` (same discipline as today's `serveHolder`).

### HTTP endpoints (serve layer)

- `GET /` → the **shell** page: a right `<aside>` sidebar + a full-height
  `<iframe>` + the sidebar CSS/JS. Generated by the serve layer (an embedded
  asset), never the converter.
- `GET /__content` → the live head's `html` (pristine document). The iframe's
  src while following Live.
- `GET /__version/{id}` → that version's `html` (pristine). `404` if unknown id.
- `GET /__versions` → JSON array of `{id, kind, label, ts}` (no html) — the
  timeline for the sidebar.
- `GET /__mtime` → the live head id as plain text (bumps only on a real content
  change, because of dedup).
- Any other path → `404` (as today).

### Shell + sidebar (embedded assets)

Following the existing `//go:embed` pattern (`internal/scripts/*.js`), add
embedded assets for the shell HTML, the sidebar CSS, and the sidebar JS (exact
file layout decided in the plan; e.g. `internal/serve_assets/`). The shell:

- Two-column layout: iframe fills the left, a fixed ~320px `<aside>` on the right.
- **Sidebar JS** fetches `/__versions`, renders the list newest-first (live head
  labelled `Live` at the top), and polls `/__mtime`:
  - **Following Live** (head selected): on an `/__mtime` bump, reload **only the
    iframe** (`iframe.src = "/__content"`) and refresh the list. Sidebar state
    persists.
  - **Viewing a snapshot** (a row clicked): `iframe.src = "/__version/{id}"`,
    that row becomes selected, auto-follow pauses, a **Back to Live** control
    appears. New saves still append to the list (a subtle "new" marker) but the
    iframe stays on the snapshot until Back to Live is clicked.
- A version row shows: a selected-dot, a kind label (`Live`/`edit`/`opened`),
  and a timestamp.

### Data flow

```
edit+save → poll goroutine detects change → render → dedup vs head →
  append version → head id bumps
shell JS polls /__mtime → sees bump → (Live) reload iframe from /__content
                                     → refresh /__versions list
click row → iframe.src=/__version/{id}, pause follow
```

## Error handling

- **Render error on a save:** store a pristine, escaped standalone error page as
  that version's `html` (no injected reload script), still bump the head — so the
  error shows live (the shell reloads the iframe to it) and a later fix appends a
  good version.
- **Unknown `/__version/{id}`:** `404`.
- Non-root/unknown paths: `404`.
- Clean `SIGINT` shutdown unchanged (`server.Shutdown`).

## Testing (`internal/serve_test.go` + a version-store test)

- **Version store unit tests:** initial `opened` version present; append on
  change; dedup skips an identical render; lookup by id; head id.
- **Serve integration test:** `GET /` returns the shell (contains the iframe and
  the sidebar script marker); `GET /__versions` starts with one version; `GET
  /__content` has the initial content; modify the file → `/__versions` grows and
  `/__mtime` bumps → `GET /__version/1` still returns the original content while
  `/__content` returns the new; a same-content `touch`-style rewrite does NOT add
  a version (dedup). Run under `-race`.
- Sidebar JS behavior (selection, iframe swap) is client-side — verified by the
  manual smoke test, not a Go test.

## Concurrency

The version store is written by the poll goroutine and read by all handlers →
`sync.RWMutex`. The existing serve goroutines (poll + shutdown) are unchanged in
lifecycle.

## Out of scope (A1)

- **Git versions** — sub-project A2 (adds a git source + `RenderBytes` for git
  content into the same store/UI).
- **Inline section diff / highlight-on-change** — sub-project B (the hard
  diff-to-rendered-region mapping).
- A `--history` flag / making the sidebar optional (it's always on).
- Persisting versions across serve restarts; a version cap; export of history.
- Editing/reverting from the UI (view-only).

## Future (context for reviewers)

A2 populates the same store with git-history versions at startup and needs
`Converter.RenderBytes([]byte) ([]byte, error)` (render source that isn't a file
on disk). B computes diffs between any two of this store's versions and highlights
changed regions — it will likely swap the iframe reload for a fetch-and-morph
content update. Neither changes A1's store or endpoints.
